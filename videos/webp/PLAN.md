# WebP解説動画 — 計画

ずんだもん (Z・聞き手) と四国めたん (M・解説)。PNG 編・JPEG 編・GIF 編の続編。想定 14〜16 分。1920×1080 / 30fps。
対象は普通の高校生。前提にしてよい知識：16 進数、前の 3 本で出てきた言葉 (フィルタ、LZ77、ハフマン符号、明るさと色、波に分ける、割って丸める)。

## 書式

docs/script-writing.md を参照 (`> Z:` / `> M(笑):`、`{cue}`、`[表記|よみ]`、行末の `(+秒)`、`→` は画面の案)。

## 素材 (data/)

- `cat.png`：猫の写真 451×300 (scikit-image の chelsea、CC0)。前の 3 本と同じ。
- `cat_q80.webp`：Pillow (libwebp) の品質 80。**本編の WebP**。16,974 バイト。`cat_q80.jpg`：JPEG 編と同じ品質 80 の JPEG。23,693 バイト。
- `cat_q{5,10,20,30,50,90}.webp`、`cat_lossless.webp`：品質を変えたもの・可逆。
- `zunda.png` (541×797、立ち絵のキャンバス全体を半分に。透明な背景) と `zunda_lossless.webp` / `zunda_q80.webp`、`zunda_anim.webp` (GIF 編のスタンプを動く WebP に)。立ち絵から作るのでリポジトリには入れない (`tools/make_data.py`)。
- 画面の数値はすべて自前の復号器 (`tools/vp8.py` 非可逆、`tools/vp8l.py` 可逆、`tools/webpanalyze.py` 箱) から取る。
  dwebp と Y・U・V の全画素が一致 (ループフィルタあり・なしの両方)、可逆は Pillow と RGBA の全画素が一致 (`tools/check_decoder.py`)。

## 主役のブロック

明るさ (Y) の **MB (横 10, 縦 7) の 4×4 の 13 番** = 画素 (164, 124) から 4×4。猫の左目の、瞳のふち (JPEG 編の主役のブロックのすぐ下)。
予想の向きは VR (下へ、少し右へななめ)。元 − 予想 の差は小さく、丸めると 16 個すべて 0。予想しないで (全部 128 と予想して) 同じ割る数で丸めると 6 個残る。

## 画面の約束

- 色：予想はシアン `CYAN`、元 − 予想 の差は紫 `PURPLE`、注目は黄、失われる・ずれは珊瑚。もう描いた所は明るく、まだの所は暗く沈める。
  算術符号の幅は青 (「はい」の側) と珊瑚 (「いいえ」の側)。
- 何度も戻ってくる図：猫の明るさ (Y) の画像と 16×16 の格子 (S03〜S07)。同じ位置・同じオブジェクトで戻す。

## S04 となりから予想 (見本シーン)

> M: {s04_01}ブロックは{order}左上から順番に作っていくわよね。{done}だから、あるブロックを作るとき{known}その上と左はもう出来上がっているの。

> M: {s04_04}予想のしかたは{rules}いくつか決まっているの。たとえば{v}上の点をそのまま下へのばす。{h}左の点を右へのばす。{dc}上と左の平均の色で全部ぬる。 (+0.6)

→ 右に決まりの欄。{v} 小さな 4×4 の図で、上の点が下へ流れて埋まる (①縦)。{h} 左の点が右へ (②横)。{dc} 平均の 1 色で埋まる (③平均)。それぞれの図は実際の主役の MB の上と左の点で作る。

> M: {tm}それから{tmrule}左の点に、上の行の変わり方を足していく予想。{tmname}「TM」というわ。

→ {tm} ④の図。{tmrule} 左の点 ＋ (上 − 左上) で埋まる。{tmname} ④に「TM」。

> M: {s04_06}細かい所は{four}16×16をさらに4×4に分けて、{ten}10通りの向きから選べるの。{diag}ななめにのばすこともできるわ。 (+0.8)

→ {four} 主役の MB が 4×4 の 16 個に分かれる。{ten} 決まりの欄が 10 本の向きの矢印に (縦・横・平均・TM と、6 つのななめ)。{diag} ななめの矢印が光る。

> M: {s04_08}ネコの目のふちで{eyeb}実際にやってみましょう。

→ {vr} 決まりの欄で VR の矢印が光る。{vrdir} まわりの点の値が、矢印の向きに沿ってマスの中へ流れ込み、隣どうしの平均になって 16 マスが埋まる (実際の予想の値、明るさの色と数字)。

## S06 算術符号

> M: {s06_01}JPEGやPNGは{huff}ハフマン符号で、{often}よく出るものに短い符号をつけていたわよね。

→ {huff} 記号と符号の小さな表 (よく出る → 短い)。

> M: {min}でもハフマン符号は、どんなによく出るものでも{onebit}最低1ビットかかるの。

→ {onebit} 一番短い符号の「1 ビット」に下線。

> Z(考): {zero}…0が9割も出るなら、1ビットでももったいないのだ？

> M(得意): そう。そこでWebPは{arith}算術符号を使うの。

→ {arith}「算術符号」。

> M: {ex}たとえば、ほっぺのこの3つのブロック。{ask}数を書く前に、それぞれ「全部0？」という問いに[はいかいいえ|ハイか、イイエ]で答えるの。

→ {ex} 猫の明るさの画像で、MB (横 8, 縦 13) の 4×4 の 0・1・2 番 (ほっぺ、横に並んだ 3 つ) が黄色の枠で光り、拡大される。{ask} 3 つの上にそれぞれ問いのカード「全部 0？」。

> Z: {plain}[はいかいいえ|ハイか、イイエ]なら、1つ1ビットで{three}3ビットなのだ。

→ {plain}「はい → 0」「いいえ → 1」。{three} 3 つのカードの下に 1 ビットずつ、合わせて「3 ビット」。

> M: ふつうはね。でも{foresee}答えが前もって予想できるなら、もっと減らせるの。{likely}まわりが全部0のときは、{p}10回のうち7回は「[はい|ハイ]」なのよ。 (+0.6)

→ {likely} 3 つのブロックのまわりも全部 0 (実際の値)。{p} 10 個の丸のうち 7 個が「はい」(青)、3 個が「いいえ」(珊瑚)。その下に「183 / 256」(実際の確率。3 つとも同じ)。

> M: {ruler}ここで、0から1までの定規を考えるわ。{bit1}1ビット目は「左半分か右半分か」。{bit2}2ビット目は、その中の左半分か右半分か。

→ {ruler} 大きな横長の定規 (0〜1)。{bit1} 真ん中で切れて、左に「0」、右に「1」。{bit2} それぞれがまた半分に切れて「00」「01」「10」「11」(幅 1/4 ずつ)。

> M: {quarter}だから2ビットあれば、定規の4分の1の場所を1つ指せるの。 (+0.6)

→ {quarter}「00」の区間 (0〜0.25) が光る。

> M: {cut}今度は、答えで定規を切っていくわ。{rule}「[はい|ハイ]」は左の7割、「いいえ」は右の3割。{a1}1つ目の答えは「[はい|ハイ]」。{w1}残るのは0から[0.71|れいてんななイチ]。 (+0.6)

→ 定規の下に 2 本目の帯 (答えの帯)。{rule} 帯が「はい」(青、左 7 割) と「いいえ」(珊瑚、右 3 割) に分かれる。{a1} 1 つ目のブロックのカードに「はい」。{w1}「いいえ」の側が消えて、0〜0.71 が残る (実際の値)。

> M: {a2}2つ目も「[はい|ハイ]」。{w2}残った所をまた7対3に分けて、0から[0.51|れいてんごイチ]。{a3}3つ目も「[はい|ハイ]」で、{w3}0から[0.37|れいてんさんなな]。 (+0.8)

→ {a2}{w2} 残った帯がまた 7:3 に分かれ、左が残る。{a3}{w3} もう一度。帯の幅が 0.71 → 0.51 → 0.37 と縮む (実際の値)。

> Z(考): {narrow}答えが3つで、だんだん細くなったのだ。

> M(得意): {look}ここで、さっきの定規と並べてみて。{p00}「00」の場所は0から[0.25|れいてんにご]。{inside}0から0.37の中に、すっぽり入っているでしょう？ (+0.8)

→ {look} 定規と答えの帯が上下に並ぶ。{p00}「00」の区間が光る。{inside}「00」の区間が答えの帯 (0〜0.37) の中に収まっていることが、縦の点線で分かる。

> M: {two}だから「00」の2ビットだけ書けば、3つの答えが全部伝わるの。

→ {two} ファイルに書くのは「00」の 2 ビットだけ。3 つのカードの「はい」から線が「00」に集まる。

> Z(驚): {lt}3つの答えが2ビットなのだ！？ 1つ1ビットより少ないのだ！
