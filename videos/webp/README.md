# WebP 編

**同じ写真が3割小さい！？WebPがJPEGに勝てる理由を1バイトずつ読んでみた【ずんだもん解説】** — https://youtu.be/pWV0v-tolTU
(約 13 分、11 シーン。動画ファイルは Release `webp-v1`)

猫の写真 (JPEG 品質 80 で 23,693 バイト、WebP 品質 80 で 16,974 バイト。元とのずれはほぼ同じ) で、
ファイルの中身 → 明るさと色・16×16 → となりから予想 → 差を波に → 算術符号 → ループフィルタ → 可逆の WebP → 透明と動き → 実験と弱点、の順に解説する。

## データの用意

`data/cat*` は猫の写真 (CC0) から作ったもので、リポジトリに入っている。
`data/zunda*` は立ち絵から作るので入っていない (動くスタンプは GIF 編の `zunda_anim.gif` から作る)。

```bash
uv run python videos/webp/tools/make_data.py                        # 立ち絵 (assets/characters) が必要
uv run python videos/webp/tools/check_decoder.py videos/webp/data/*.webp   # 自前の復号器の確かめ (dwebp が必要)
```

## この動画で決めたこと

- 主役の 4×4：MB (横 10, 縦 7) の 13 番 (画素 (164, 124)、猫の左目の瞳のふち)。予想の向きは VR、丸めると差は全部 0。
- 算術符号の例：MB (横 8, 縦 13) の 0〜2 番 (ほっぺ)。3 つとも「全部 0？→はい」(確率 183/256)。答えの区間 0〜0.37 に「00」(0〜0.25) が入るので 2 ビット。
- ループフィルタは品質 10 で見せる。ならされるかどうかは段の大きさではなく、まわりが平らかどうか (この品質ではどの段も大きさの上限より小さい)。
- 可逆の「最近の色の表」に入るのは、緑を引いて予想したあとの差 (色そのものではない)。
- イラストは立ち絵のキャンバス全体を半分にしたもの (切り抜いてから縮めると縦横比が崩れる)。
