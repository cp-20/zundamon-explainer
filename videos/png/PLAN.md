# PNG解説動画 — 計画

ずんだもん（Z・初学者）と四国めたん（M・解説）。想定 12〜14 分。1920×1080 / 30fps。

## 書式

- `> Z:` / `> M:` が台詞。`Z(驚):` のように表情を付けられる（通常・笑・驚・困・考・得意・指）。
- 台詞中の `{name}` は**キュー**。その位置の mora の開始時刻を VOICEVOX の結果から計算し、画面はその時刻に合わせて変わる。字幕には出ない。
- `[表記|よみ]` は字幕は表記、音声はよみ。
- 行末の `(+1.2)` は、その台詞のあとに置く**間**（秒）。大きく画面が変わる所・数字をじっくり見せたい所では、喋り続けずに間を作る。
- `→` の行は画面の変化。**太字**は前の画面から同じオブジェクトのまま続くもの。
- 画面の数値はすべて `tools/pnganalyze.py` が `data/` から計算した `build/analysis/*.json` から取る（台詞の数値も同じ値を丸めたもの）。

## 画面の約束

- 背景は濃紺に近い黒 `#14161c`。文字は Zen Maru Gothic、バイト列は JetBrains Mono。
- 領域：立ち絵は左下（Z）と右下（M）、字幕は2人の間の下端。図はそれ以外（`pv/layout.py` の `SAFE`）。
- 色：Z `#7cc35a`、M `#e3609a`。フィルタ5種は None 灰 / Sub 青 / Up 黄 / Average 紫 / Paeth 珊瑚。データの「元」は白、「コピー」はシアン。
- 強調の使い分け：**拡大**（今から話す1つ）、**下線**（ラベルや数値を読む）、**文字色**（種類の区別）、**揺らす**（意外・異常）。囲み枠は使わない。
- 地図（S04）は以降のシーン冒頭と末尾に戻る。地図そのものは同じ配置で、今いる段だけ拡大・着色する。

> Z(考): じゃあ、残りの5つは何なのだ？

→ {broken} `0D` が抜けて後ろが詰まり、詰まったバイトが珊瑚色で揺れる。本来の並び（暗い）が下に残る。

> Z(驚): 1バイト抜けただけで、ずれて合わなくなるのだ。

> Z(驚): たった8バイトで、{ok}ちゃんとPNGか確かめられるのだ！ (+0.6)

## S03 チャンク

> M: {s03_01}シグネチャの後ろには、{chunk}チャンクという箱が並んでいるわ。 (+0.8)

→ ダンプのシグネチャ以降が、最初のチャンク（IHDR, 25バイト）ぶん切り出されて横一列に。

> Z: 箱？ 中には何が入っているのだ？

> M: いろいろよ。でも、どの箱も同じ形。{len}最初の4バイトが中身の長さ、{type}次の4バイトが種類の名前、{data}その後ろに中身、{crc}最後に、壊れていないか確かめるための4バイトが付くの。 (+0.6)

→ 4区間に順に色が付き、下にラベル「長さ」「種類」「データ」「CRC」。

> Z: 長さは0Dだから{n13}13バイト、種類は…{ihdr}IHDRなのだ。 (+0.6)

→ `00 00 00 0D` → `13`、`49 48 44 52` → `I H D R`（同じオブジェクトのまま）。

> M: {s03_04}正解。[IHDR|アイエイチディーアール]は画像の基本情報。{w}幅が1082、{h}高さが1594。

> Z(笑): 僕の画像の大きさなのだ！

> M: {depth}1色8ビットで、{ctype}色の形式6は、RGBと透明度。つまり{four}1画素4バイトということね。 (+0.8)

→ データ13バイトが順に `1082` `1594` `8` `6` に変形し、上にラベル。{ctype} に「6 = RGB＋透明度 → 1画素 4バイト」。

> Z(驚): {s03_05}大きさまで、ファイルの先頭に書いてあるのだ！

> M: {s03_06}ファイル全体をチャンクごとに並べると、{ribbon}こうなるわ。 (+1.0)

→ ファイル全体を長さに比例した帯に（IHDR のバイトが帯の左端に縮む）。IHDR・IEND は細いので引き出しラベル。

> Z: {most}ほとんど[IDAT|アイダット]なのだ。

→ IDAT が明るく、ほかは暗く。

> M: [IDAT|アイダット]が画像の本体。{six}6つに分かれているけど、{join}つなげれば1本のデータになるわ。

> Z(考): わざわざ分けているのは、なんでなのだ？

> M: 書く側の都合よ。少しずつ書き出せるように区切っているだけで、切れ目に意味はないの。

> M: {iend}最後の[IEND|アイエンド]は、「ここで終わり」の印。 (+0.6)

→ {six} 6つの IDAT の写しが下へ降りて離れ、長さが出る。{join} 詰まって1本「332,957 バイト」。{iend} IEND に「ここで終わり」。

> M: {s03_09}それから、チャンクには{optional}飛ばしてもいいものもあるの。

> Z: 飛ばしていい箱なんて、あるのだ？

> M: {s03_10}試しに、この画像に{text}文字情報の[tEXt|テキスト]と、{time}更新日時の[tIME|タイム]を入れてみたわ。 (+1.2)

→ 実際に作った `zundamon_meta.png` の帯。IHDR の後ろに tEXt・tIME が割り込み、中身の文字列を表示。

> Z(困): 知らない箱が増えたのだ。読む方は困らないのだ？

> M: {s03_11}種類の名前の{case}1文字目が小文字なら、なくても絵は描ける、という約束なの。 (+1.0)

→ 名前の一覧。1文字目が拡大し、大文字（必須）と小文字（なくてよい）で色が分かれる。

> M: {s03_12}知らないチャンクに出会ったら、{skip}長さを読んで、その分ジャンプすればいい。 (+1.0)

→ 帯の先頭が拡大され、読み取り位置の矢印が進み、tEXt・tIME で長さを読んで弧を描いて跳ぶ。

> Z(笑): {s03_13}わかったのだ！ だから長さが先頭にあるのだ。{same}絵もちゃんと同じなのだ。 (+1.5)

→ 2つのファイルから復元した画像が並んで「＝」。最後に全部消える。

## S05 フィルタ（見本シーン）

> M: まずは、フィルタから見ていくわ。

> Z: {what}数字を整えるって、どういうことなのだ？

→ {what} **地図**が上端の細い帯に縮み、フィルタ段だけ塗りつぶし（以降ずっと上に残る）。

> M: {s05_02}このグラデーションの画像で見てみましょう。{row}一番上の行の、{red}赤の値を左から並べるわ。 (+0.6)

→ `gradient.png` が中央上に。{row} 一番上の行が白く光り、その先頭12画素が実際の色の箱になって下へ降り、横一列に並ぶ。{red} 箱が暗くなり、赤の値 `40 40 40 41 …` が入る。左上に「赤の値」。

> Z: {read}40、40、40、41…。少しずつ増えているのだ。

> M: そう。少しずつ増えるだけで、{same}同じ並びが二度と出てこない。これだと、圧縮の得意な「くり返し」が見つからないの。

→ {same} 先頭3つに下線。その写しが飛んで `41 41 41` に重なり、合わずに赤くなって揺れ、消える。

> M: そこで、{sub}1つ左との差を書くことにする。これがSubフィルタ。 (+0.8)

→ 「Sub：左との差」と、隣どうしを結ぶ弧。数字が左から順に差 `40 0 0 1 0 0 1 …` に変わる（同じオブジェクト）。

> Z(驚): {diff}0と1ばっかりになったのだ！ くり返しだらけなのだ。

→ 0 は暗く、1 は黄色で拡大。`0 0 1` の写しが次の `0 0 1` に飛んでぴたりと重なる（さっきと対比）。

> Z(困): でも、数字を書き換えちゃって大丈夫なのだ？

> M: 差なら、{undo}左から順に足していけば元に戻せる。だから何も失わないわ。

→ 下側の弧が左から順に伸び、数字が元の値へ戻っていく。

> Z: 左から足していけば元通り…。なるほどなのだ！

> M: {s05_07}フィルタは5種類。{none}何もしないNone、{sub2}左との差のSub、{up}上との差のUp、{avg}左と上の平均との差のAverage、{paeth}そしてPaeth。 (+0.8)

→ 列の中の2マスがそのまま「a（左）」「x（今）」になり、上に「c（左上）」「b（上）」が降りて近所図に。図が4つ複製されて横に飛ぶ。名前を言うたびに、その種類が使うマスがその色に塗られ、名前が出る。

> Z(困): {hard}Paethだけ、なんだか難しそうなのだ。

> M: {s05_08}Paethは、まず{pred}「左＋上−左上」を計算するの。

→ 他の4つは左上で「番号の色札＋名前」の凡例に縮む。Paeth の図が拡大し、{pred} 実データ（グラデーション4行目・Paeth で圧縮された行）の c=40, b=41, a=40 が入る。右に式 `a + b − c`。

> M: 左上から上へ{slope}いくつ増えたかを、{add}左に足すってこと。上の行と同じ増え方をする、と考えるのね。

→ {slope} c→b に矢印「+1」。{add} その「+1」が a の下へ飛び、a→x の矢印になる。

> Z(考): 上の行は{inc}1増えたから、こっちも40から1増えて{p41}41、ってことなのだ？

→ {p41} 数字が飛んで式 `40 + 41 − 40 = 41`。

> M: そう。そして{near}左・上・左上の3つのうち、{pick}この41に一番近いものを、予想に使うの。 (+0.6)

→ {near} 各マスの外に差の丸札 1・0・1。{pick} 0 の b が黄色で拡大、b の値が x へ飛ぶ。x の本当の値も 41 で、書く差は 0。

> Z(困): {why}計算した41をそのまま使えばいいのに、なんで選び直すのだ？

> M: {edge}色の境目で差が出るの。ずんだもんの{zoom}輪郭のここを見て。 (+1.0)

→ グラデーションの例は左へ縮む。`zundamon.png` の輪郭（448行目・616列）へズームし、6×6 画素を実際の色で。{zoom} その中の 2×2（c b / a x）を持ち上げ、緑の値 141・255・250 を入れる。

> M: 左上だけが{dark}線の色で暗い。式で計算すると{p364}364。

→ {dark} c が揺れる。{p364} `250 + 255 − 141 = 364` が出て、364 が赤く揺れる。

> Z(驚): 364？ {max255}1バイトは255までなのだ！

> M: そう、ありえない値。でも、{pick2}一番近い上の255を選べば、{hit}本当の値とぴったり同じ。 (+0.5)

→ 差の札 114・109・223、b が選ばれて x へ飛ぶ。{hit} x の本当の値 255 と重なり、差 0。

> Z(笑): 境目でも{got}ちゃんと当たるのだ！

> M: {s05_17}どれを使うかは{each}1行ずつ選べて、{tag}選んだ番号を行の先頭に1バイト書いておくわ。

→ Paeth も凡例に入る。`zundamon.png`（透明は市松模様）。{each} 走査線が 420 行目へ降り、その行の実際の画素が帯になって右へ引き出される。{tag} 凡例の「4」の札が飛んで帯の先頭に付き「+1バイト」（この行は実際に Paeth）。

> Z: 行ごとに、合うフィルタを選べるのだ！

> M: {s05_18}ずんだもんの画像で、{stripe}行ごとに選ばれたフィルタを色で塗るとこう。 (+1.0)

→ 帯は元の行へ戻り、{stripe} 画像の右に 1594 行ぶんの色帯が上から現れる。凡例の横に本数の棒（169 / 109 / 678 / 227 / 411）。

> Z: {most}Upが一番多いのだ。

→ Up の行が拡大、色帯の Up 以外が暗くなる。

> M: 上の行とよく似た行が多い、ということね。

> M: {s05_20}フィルタの前とあとで、{hist}バイトの値の数を比べてみて。

→ グラデーションのバイト値 0〜255 の分布（フィルタ前）。

> Z: 前は、いろんな値にばらけているのだ。

> M: 最後の段は、{title}ハフマン符号よ。

> Z(考): どうやって決めるのだ？
