# 書き出しの速さ

直しては見る、のくり返しを速くするための仕組みと使い方。

## 使い方

```bash
bin/pipeline.sh gif S05                    # シーン全体 (540p)。検査とシートも作る
bin/pipeline.sh gif S05 --line S05_18      # その台詞のあたりだけ (直した所を見る)
bin/pipeline.sh gif S05 --from 100 --to 130
bin/pipeline.sh gif S05 --res 1080         # 本番の大きさ
bin/build_all.sh gif                       # 通し (1080p)
```

部分だけの書き出しは `videos/<name>/build/out/S05@<開始>-<終了>.mp4` に出る (音付き)。検査とシートはシーン全体のときだけ作る。
部分の書き出しでも、その範囲にかかるアニメーションは最初から最後まで描く。

## 測った速さ (GIF 編、540p、16 コアの CPU と RTX 3050 Ti)

| 書き出し | 前 | 今 |

| S07 (40 秒) のシーン全体 | 約 120 秒 | 約 39 秒 |

| 通し (1080p、10 分の動画) | 約 60 分 | 約 13 分 |

## 仕組み

`zunda/build.py` が書き出しをまとめて行う。

1. **時間で分けて並行に描く**：Manim の描画は 1 プロセスで 1 コアしか使わない。シーンを数秒ずつの「かけら」に分け、別々のプロセスで同時に描く (`config/render.yaml` の `chunk_seconds`)。
   かけらより前の部分は、描かずに状態だけ進める (`zunda/scene.py` の `PV_FROM`・`PV_TO`。Manim の skip に加えて、skip 中は画面の計算も止める)。
2. **かけらのつなぎ目をそろえる**：Manim は描くときはフレーム単位で、skip のときは秒のまま時刻を進めるので、かけらの境目がわずかにずれる。
   境目を次のかけらの開始フレームで決め、各かけらをちょうどその枚数にそろえてから、再エンコードせずにつなぐ。1 プロセスで描いたものとフレームの数も中身も一致する。
3. **立ち絵と字幕の合成も並行**：描き終わったかけらから重ねる。合成は整数の掛け算 1 回と足し算 1 回 (前もって色×α を計算した立ち絵)。立ち絵は `cache/sprites/` に残して、プロセスをまたいで使い回す。
4. **GPU で書き出す**：NVIDIA の GPU があれば、Manim の書き出しと合成の書き出しに NVENC を使う (`encoder: auto`)。合成では RGB のまま渡し、色の変換も GPU にまかせる。
5. **Manim 自体の重い所を差し替える** (`zunda/fastcam.py`)：
   - Text の 1 文字ごとに付いている SVG のパスを、図形の deepcopy で複製しない (Manim はアニメーションのたびに図形をまるごと複製する。描画時間の大半がこれだった)。
   - 画像は、画面全体ではなく、画像のかかる範囲だけに重ねる。不透明度 0 の画像は描かない。
6. **それ以外**：音・検査・シートを同時に作る。シートは動画を 1 回読むだけで全部のフレームを取り出す。
   依存のバイトコードを入れるときに作る (`pyproject.toml` の `compile-bytecode`。環境に `PYTHONDONTWRITEBYTECODE` があると、Manim の import が毎回 10 秒かかっていた)。

## シーンを書くときに気をつけること

- 部分の書き出しは、シーンを最初から skip で進めるので、`construct` の中の重い前処理 (大きな表の計算、画像の読み込み) はシーンの頭で 1 回だけ行う。アニメーションのたびにやらない。
- 時刻を `self.at(秒)` で直接書かない (台詞のキューにする)。かけらの境目で時刻がずれない。
- 動く画像を毎フレーム差し替えるような重い所は、かけらが偏って遅くなる。`chunk_seconds` を小さくすると均せる。
