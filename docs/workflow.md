# 動画づくりの流れ

1 本の動画（10〜18 分）を、計画 → 見本 1 シーン → 残りを並行 → 通しの順で作る。
人（依頼者）の確認は「計画と見本」「通しの試写」の 2 か所でもらい、その間はエージェントが進める。

## 0. 準備

- 環境と素材：[setup.md](setup.md)。VOICEVOX が動いているか `curl 127.0.0.1:50021/version` で確かめる（PC の再起動で止まっていることがある）。
- 新しい動画のフォルダ：`videos/<name>/` を作り、[templates/](templates/) の `video.yaml` `PLAN.md` `AGENT_BRIEF.md` を写す。

## 1. 題材のデータと解析器

- 題材のファイル（画像など）を `data/` に用意し、その形式を**自前で読み解く解析器**を `videos/<name>/tools/` に書く。
  画面に出す数字（バイト数・係数・符号など）は全部ここから取る。
- 解析器は既存の実装（Pillow など）と突き合わせて、結果が一致することを確かめる（例：GIF は全コマが 1 画素も違わない、JPEG は輝度が ±1）。
- 見せたい現象がはっきり出る実データの場所を、データから探して選ぶ（目で選ばない）。例：段がいちばん目立つ範囲、2 色だけでできた小さな区画。
- 再配布できない素材から作ったデータ（立ち絵から作った画像など）はコミットしない。作り方を `tools/` に置く（[publishing.md](publishing.md) のライセンス）。

## 2. 計画（PLAN.md）

- 台詞と画面の案をシーンごとに書く。書式と台詞の作り方は [script-writing.md](script-writing.md)。
- 動画の構成：日常的な場面から入るフック → 仕組みを順に → 実験・比較 → まとめ → クレジット。
- 書いたら `bin/voice.sh <name>` で音声を作り、全台詞の読み（`kana`）を確かめて直す（[audio-and-subtitles.md](audio-and-subtitles.md)）。

## 3. 見本のシーンを 1 つ作って確認をもらう

- いちばんの見せ場（その動画の中心の仕組み）を、自分で 1 シーン作る。これが残りのシーンの品質の基準になる。
- `bin/pipeline.sh <name> SNN` で 540p の試写を作り、検査 0 件・シートを目で確認してから、試写と PLAN.md を依頼者に渡す。
- 指摘をもらったら、指摘された所だけを直して、もう一度見せる。見本が通るまで残りに進まない。
- 見本で決まった「分かりやすさの基準」や、踏んだ落とし穴は `AGENT_BRIEF.md` に書き足す。

## 4. 残りのシーンを並行で作る

- シーン担当のエージェントに、`AGENT_BRIEF.md` と見本のシーンを読ませて並行で作らせる（[agents.md](agents.md)）。
- 届いたものは必ずシートと切り出したフレームで見る。エージェントは文字や図を小さく作りがちなので、そのたびに大きさと配置の直しを頼む。
- シーンのつなぎ目（前のシーンの最後の画面＝次のシーンの最初の画面）は、計画の時点で表にして全員に渡しておく。

## 5. 通しで作る

- `bin/build_all.sh <name>` で 1080p の通しを作る（4 並列で 1 時間前後）。
- 確かめること（[quality-checks.md](quality-checks.md)）：全シーンの検査 0 件、つなぎ目の差、音量 −14 LUFS、
  1080p から何枚か切り出して文字の大きさ、チャプターの時刻。
- 480p の試写版と概要欄（`build/out/description.txt`）を依頼者に渡す。確かめていないこと（音を聞いていない、動きを通しで見ていない、など）も添える。

## 6. 指摘を直す

- 直したシーンだけを 1080p で描き直し、`uv run python -m zunda.master all`（`ZX_VIDEO=<name>`）で音と結合をやり直す。
- 台詞を直したら、その台詞の音声を作り直す。キューの位置が変わるので、そのシーンは描き直しが必要。
- 間の長さなど全体の音声のタイミングを変えたら、全シーンの描き直しになる。秒数を直接書いた所（`self.at(12.3)`）は台詞のキューに置き換えておく。

## 7. 公開の準備

- タイトル案とサムネ案を複数出す（[publishing.md](publishing.md)）。依頼者が選んだものを `video.yaml` に書く。
- 動画ファイル・サムネ・概要欄は GitHub の Release に置く（リポジトリには入れない）。
