# 台詞の書き方 (PLAN.md)

## 書式

`videos/<name>/PLAN.md` が台詞の唯一の置き場所。`zunda/script.py` が読む。

```markdown
## S05 フィルタ                      ← シーンの見出し (SNN と題名)

> M: {s05_01}まずは、フィルタから見ていくわ。
> Z(驚): {zero}ほとんど0になったのだ！ (+1.2)
→ {zero} 0 のマスが暗く沈む。          ← 画面の変化 (たたき台。コードは読まない)
```

| 書き方 | 意味 |
|---|---|
| `> Z:` / `> M:` | 台詞。Z＝ずんだもん、M＝四国めたん |
| `Z(驚):` | 表情。`通常・笑・驚・困・考・得意` (`config/characters.yaml`) |
| `{name}` | キュー。その位置の音が出る時刻に画面を合わせる。字幕には出ない |
| `{s05_01}` | 台詞の頭に置く慣習のキュー (シーン番号＋行番号) |
| `[表記\|よみ]` | 字幕は表記、音声はよみ (`[FF D8\|エフエフ、ディーハチ]`) |
| 行末の ` (+1.2)` | その台詞のあとに足す間 (秒) |
| `→ ...` | 画面の変化の説明。**太字**は前の画面から同じオブジェクトのまま続くもの |

- 作業中に担当者が台詞を変えるときは PLAN.md を直接直さず、`videos/<name>/script/SNN.md` に節ごと写して直す (あれば PLAN.md より優先される)。並行作業での衝突を避けるため。
- 字幕と読みは英数字と和文の間の空白を詰める。英数字どうしの空白 (`255 255`) は残る。

## 2 人の役割

- **めたん (M) が進行と解説**。話題を次へ移す、まとめる、新しいことを紹介するのはめたん。
- **ずんだもん (Z) はリアクション役**。驚く、分からないと言う、素朴な疑問を出す、視聴者が抱きそうな疑問を代わりに言う。進行はしない。
- ずんだもんの台詞は多めに。めたんが一方的に講義しないで、掛け合いで進める。
- ずんだもんは物分かりが良すぎないように。鋭い推理で先回りしない。めたんが「この数字を見て。何か気づかない？」と画面を指し、ずんだもんが自信なさげに気づく、くらいの距離感。
- 視聴者が知らないことを、ずんだもんに持ち出させない (例：保存時の品質の設定)。そういう話題はめたんが紹介する。
- 口調：ずんだもんは「〜のだ」「〜なのだ」、納得は「なるほどなのだ！」「わかったのだ！」 (「〜なのだな」で締めない)。めたんは「〜わ」「〜のよ」「〜かしら」。

## 言葉

- 対象は普通の高校生。数式は四則演算まで。用語は使う前に日常の言葉で説明する。
- 略語は何の略かを言う (例：DCT＝Discrete Cosine Transform、離散コサイン変換)。
- あいまいな言葉を避ける。「量」ではなく「何倍して足したか」のように、やっていることをそのまま言う。
- 一般的な呼び方に合わせる (例：JPEG の quality は「画質」ではなく「品質」)。
- 前提にしてよい知識は動画ごとに決めて揃える (例：16 進数は知っている前提で、バイトの並び順だけ説明する)。
- 前の動画と関係する所は、前の動画の言葉で結びつける (「PNG の LZ77 は『何バイト前をコピー』だったけど、LZW は『辞書の何番』」)。

## 構成

- **フック**：日常的な場面から入る (「スタンプを作ったのだ」「写真を撮ったのだ」)。いきなり数字から始めない。
  驚きは、視聴者が知っているもの (前の形式など) との比較で作る (「PNG 1 枚より GIF 8 枚のほうが小さい」)。
- 技術的な画面 (画素への拡大など) は、それを言う台詞のところで初めて出す。
- **中身**：仕組みを 1 つずつ。各シーンは「疑問 → 小さな実例でやってみる → 結果 → ずんだもんの反応」の形が分かりやすい。
- 疑問を残さない。説明を聞いた人が次に思う疑問 (「データの中に印と同じ FF が出たら？」「辞書を送らないのにどうして読めるの？」「なぜ 258 番から？」) を、ずんだもんに言わせて答える。
- **まとめ**：工程をふり返る。最後の決め台詞はずんだもん。
- **エンディング**：まとめの台詞のあと、間 (2〜3 秒) をとって図を消しクレジットを出す。「見てくれてありがとうなのだ！」「またね。」はクレジットの画面で言う。

## 間

- 大きく画面が変わる所、数字をじっくり見せたい所では、台詞の行末に ` (+0.8)`〜` (+1.5)` の間を入れ、その間に変形や答えを見せる。
- 間には必ず見せるものがあること。画面が止まったままの長い無音は作らない。
- 台詞と台詞の間、文の切れ目の間は `config/voice.yaml` で全体に効く ([audio-and-subtitles.md](audio-and-subtitles.md))。

## 長さ

- 1 つの台詞は字幕 2 行に収まるくらいが目安。長いと自動でページ送りになる。
- 説明を丁寧にした結果シーンが長くなるのはよい。ただし同じことのくり返しは削る。
